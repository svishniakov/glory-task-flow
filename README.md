# Glory Taskflow

`Glory Taskflow` помогает готовить задачи для Jira: формулировать, проверять, сокращать и декомпозировать Feature, Task, Research, Spike и Sub-task.

Скилл основан на канонической странице Confluence `Payments-003: Подход к формированию описаний задач`.

## Как запускать

Скилл запускается только явно. Поставь имя скилла в начало сообщения:

```text
$glory-taskflow <запрос>
```

Также работают варианты:

```text
Glory Taskflow <запрос>
glory-taskflow <запрос>
глори таскфлоу <запрос>
```

## Пустой запуск

Если вызвать скилл без текста:

```text
$glory-taskflow
```

он сразу запустит intake wizard и задаст первый вопрос:

```text
Что хотим сделать?
```

Дальше скилл будет по одному собирать недостающие вводные:

- что хотим сделать;
- зачем это нужно;
- какую проблему решаем;
- какой результат ожидаем;
- какие ограничения или открытые вопросы уже известны.

После этого он определит тип задачи и подготовит Jira-ready черновик.

## Примеры использования

Создать задачу из идеи:

```text
$glory-taskflow Сделай Jira task из идеи: нужно добавить fallback на старый источник балансов, если новый provider недоступен.
```

Проверить готовое описание:

```text
$glory-taskflow Проверь описание задачи:
<текст задачи>
```

Сократить длинный текст:

```text
$glory-taskflow Сократи до Jira-ready формата:
<длинный текст>
```

Разбить Feature на задачи:

```text
$glory-taskflow Разбей эту Feature на задачи по 1-3 SP:
<описание feature>
```

Сформировать Research / Spike:

```text
$glory-taskflow Оформи Spike: нужно понять, как сейчас считается available balance и где лучше добавить проверку лимитов.
```

## Что скилл делает

Кратко:

- готовит Jira-ready описания задач;
- проверяет и сокращает черновики;
- помогает декомпозировать крупную работу;
- оформляет Feature, Task, Research, Spike и Sub-task.

Подробные правила работы, ограничения и форматы описаны в `SKILL.md`.

## Установка через AI-агента

Не нужно ставить скилл вручную. Скорми prompt ниже AI-агенту: Codex, Claude Code или другому агенту, который умеет работать с файлами.

Агент должен установить скилл глобально, не в папку проекта. Так он будет доступен всем AI-агентам этого пользователя, которые читают глобальные skills.

Для Codex глобальный путь:

```text
~/.codex/skills/glory-taskflow
```

Для Claude Code или другого агента используй его глобальную папку skills. Если агент поддерживает несколько хостов, попроси его установить копию в каждый глобальный каталог, который он реально использует.

## Prompt для установки

```text
Установи skill `glory-taskflow` глобально для текущего пользователя из GitHub:

https://github.com/svishniakov/glory-task-flow

Требования к установке:

1. Установи skill в глобальную папку skills текущего AI-агента, а не в папку проекта.
2. Для Codex используй путь `~/.codex/skills/glory-taskflow`.
3. Если работаешь с Claude Code или другим агентом, используй его глобальную папку skills.
4. Скопируй файлы репозитория как есть: `SKILL.md`, `references/`, `README.md`.
5. Не добавляй внешние инструменты, токены, cookies, API keys или локальные machine-specific файлы.
6. После установки проверь, что skill доступен по `$glory-taskflow`.
7. Если есть валидатор skills, запусти его.
```

Правила работы скилла не нужно переносить в prompt установки. Они уже описаны в `SKILL.md`.

## Проверка после установки

Минимальная проверка:

```text
$glory-taskflow
```

Ожидаемый ответ:

```text
Что хотим сделать?
```

Проверка с задачей:

```text
$glory-taskflow Сделай Task: нужно добавить логирование ошибок при неуспешной синхронизации баланса.
```

Ожидаемый результат: компактное Jira-ready описание с Context, Goal, Scope, Acceptance Criteria и Definition of Done.
